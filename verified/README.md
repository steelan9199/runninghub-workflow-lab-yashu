## 入库标准（六条都要满足）

1. 老板在成片层面确认「可以」，不是「先放着」。
2. 结构自洽：`check.mjs` 通过（连线双向、必填输入齐全、红/橙配色到位）。
3. 参数已落到不可再猜的默认值，注释卡写在图里。
4. 有 `record.md`：用途、拓扑、默认参数、实测数据、已知限制、复现命令。
5. 目录名是**中文语义名**（模型 + 适用场景 + 关键技法，如 `H3-双人换人-近景对话-二采`），禁止 `v1`、`test`、日期、纯英文代号；场景一句话同时写进本表与 `record.md` 第一段。
6. 包根有 `cover-3x4.jpg`：严格 3:4（推荐 1680×2240），**图内含主标 + 一行副标**（霞鹜文楷叠字，不许模型直出中文），无可识别影视/明星面孔；文案同步进 `record.md`「封面」小节。

## 包内固定结构

```
<名称>/
├─ workflow.ui.json   可直接导入，优先给老板用这个
├─ build.mjs          生成器，相对路径，读同目录 templates/
├─ check.mjs          自检脚本
├─ templates/         官方 UI 模板（保真控件顺序，缺了生成器跑不起来）
├─ assets/            素材原图（**不入库**，见下）
├─ cover-3x4.jpg      平台封面（唯一入库的图片，.gitignore 已开白名单）
└─ record.md          记录卡
```

**素材图片不入库**：仓库里 `*.png` / `*.jpg` / `*.mp4` 全被 `.gitignore` 排除（单张 1.5MB，纯体积负担），**唯一例外是各包的 `cover-3x4.jpg`**。克隆后要跑，按 `record.md` 里的提示词重新生成素材并上传换 `fileName`；本地工作区的 `assets/` 里仍保留原图。

## 复用方式

新片子要基于已验证的结构改：整目录复制，改 `build.mjs` 顶部四个常量（提示词 / 分辨率 / 时长 / 切点），重新生成并自检。**不要**从零搭线——模板里的控件顺序是实测过的，手写必错位。
